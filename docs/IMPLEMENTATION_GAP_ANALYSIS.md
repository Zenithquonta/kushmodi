# Kush Modi — Living Observatory 3D Portfolio
# Implementation Gap Analysis & Strict Execution Plan

**Baseline source:** Agent briefing dated 2026-10-02  
**Target specification:** `docs/PORTFOLIO_3D_WORLD_SPEC.md`  
**Current product:** Static ES-module Three.js website, Milestone 1  
**Current status:** Website M1 is live; walkable portfolio world is the next major implementation track.

---

## 0. Executive Decision

The current website already has the **correct technical foundation and visual seed** for the target experience.

**Do not rewrite the existing 3D site.**

The existing M1 already provides:

- pixel-rendered 3D hill
- telescope
- shed
- rover
- van
- drone pad
- Mumbai skyline
- browser-computed real sky
- Moon and planets
- fading astronomical trails
- weather/time HUD
- telescope readout
- keyboard/mouse controls
- touch controls
- text fallback
- browser tests

The main gap is not the renderer.

The main gap is that the current scene is still a **single observatory environment**, while the target is a **walkable portfolio world with distinct locations, physical navigation, collision, interactive objects, and project panels**.

Therefore the implementation strategy is:

> **Keep the existing world, sky, renderer, controls, live-data pipeline and visual language. Expand the terrain and scene into a connected explorable world, then add data-driven portfolio interactions.**

# 8. P0.3 Implement Reliable Ground Collision

The user must never:

- fall through terrain
- float above terrain
- walk through the ground
- become stuck inside a building

Minimum systems:

```text
player position
      ↓
terrain height query
      ↓
ground clamp
      ↓
collision resolution
      ↓
camera follows
```

Buildings and large props need simple collision volumes.

Use simplified collision geometry.

Do not use expensive per-triangle physics for every grass blade or rock.

---

# 9. P0.4 Third-Person Camera

The target specification calls for a third-person exploration camera.

Implement:

```text
Player
  │
  └── Camera boom / follow offset
          │
          └── Camera
```

Requirements:

- smooth follow
- mouse orbit
- terrain-aware camera
- obstacle-aware camera
- no clipping through buildings
- sensible zoom
- controlled pitch
- no motion sickness-inducing acceleration

The existing first-person/free-camera controls should remain available during development if they make debugging easier, but the final presentation should use the third-person exploration model.

---

# 10. P0.5 Interaction System

Replace isolated target behavior with a general interaction model.

Every interactive object should implement the same conceptual interface:

```js

  id: "aerolink",
  prompt: "INSPECT",
  action: () => openProject("aerolink")
}
```

Conceptually:

```text
PLAYER
   │
   ▼
nearest interactable
   │
   ▼
distance check
   │
   ▼
prompt
   │
   ▼
E / click / touch
   │
   ▼
action
```

Do not hardcode project logic inside every model.

# 11. P0.6 Portfolio Data Model

Suggested:

```js

    title: "AeroLink",

    location: "uav-field",
    description: "...",
    technologies: [],
    media: [],
    links: {}
  }
```

Physical objects reference IDs.

Example:

```js

```

This keeps content separate from world geometry.

# 33. Architecture Principle

The simplest viable implementation wins.

Prefer:

```text
plain ES modules
small data objects
simple collision volumes
simple interaction registry
reusable meshes
static assets
```

Avoid premature:

```text
ECS
game engine abstraction
dependency injection
state-management framework
backend API
database
complex build pipeline
```

# 34. Definition of Done — P0

P0 is complete when a new visitor can:

1. Enter the world.
2. Move around.
3. See the terrain.
4. Walk between locations.
5. Not fall through terrain.
6. See the third-person avatar.
7. Find an interactive object.
8. Receive an interaction prompt.
9. Open a project panel.
10. Close it.
11. Continue walking.
12. Discover another project.
13. Reach the observatory.

At this point the site is genuinely a **walkable portfolio**, rather than a 3D scene.
